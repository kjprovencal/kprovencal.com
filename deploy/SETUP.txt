DigitalOcean droplet — one-time setup (run as root or sudo)
================================================================

1) Packages
   apt update && apt install -y nginx ufw certbot python3-certbot-nginx

2) Deploy directory (match GitHub secret DEPLOY_PATH, e.g. /var/www/kprovencal)
   mkdir -p /var/www/kprovencal/dist
   # Put the GitHub SSH user in the www-data group so it can share dist/ with nginx without world-readable files:
   #   usermod -aG www-data github-deploy
   # (log out/in or `newgrp www-data` so the extra group applies to SSH sessions.)
   # Own the tree by that user; use group www-data on dist/ so nginx can read via group permission:
   #   chown -R github-deploy:www-data /var/www/kprovencal
   # Optional setgid on dist (once): chmod g+s /var/www/kprovencal/dist — new subdirs may inherit group www-data.
   #
   # CI installs the API binary with `install -m 755 -o www-data -g www-data`, then `chgrp -R www-data dist/`
   # each deploy so nginx can read via the group bit (Vite output is usually 644/755 already).
   # Optional once on the server — setgid on dist so new subdirs inherit group www-data:
   #   sudo find /var/www/kprovencal/dist -type d -exec chmod g+s {} +
   #
   # Passwordless sudo for the deploy user (paths may vary): install, chgrp, rm, systemctl.
   # Easiest alternative: SSH_USER=root with the key in root’s authorized_keys.

3) API environment
   Each deploy to main writes /etc/personal-site-api.env (mode 600, root:root)
   from GitHub repository secrets. The next deploy replaces the whole file.
   Do not commit the values. Copy what is on the droplet into GitHub before
   the workflow that writes this file reaches main. If SESSION_SECRET or
   ADMIN_PASSWORD_BCRYPT is missing, that deploy stops before it changes the
   file or the API binary.

   Required secrets:
     SESSION_SECRET           at least 32 characters (openssl rand -base64 32)
     ADMIN_PASSWORD_BCRYPT    output of: go run ./cmd/hashpassword 'your-password'

   The workflow always sets:
     LISTEN_ADDR=127.0.0.1:8080
     APP_ENV=production
     TRUST_PROXY=1
     BADGER_PATH=$DEPLOY_PATH/data/badger

   Optional secrets, written only when set:
     TURNSTILE_SECRET_KEY
     CORS_ORIGIN                 only if HTML is served from another origin
     LOG_LEVEL                   debug, info, warn, or error
     LOG_PATH
     HOST_STATUS_PATH
     ADMIN_SESSION_HOURS
     RATE_LIMIT_GET_MAX
     RATE_LIMIT_POST_MAX
     RATE_LIMIT_DISABLED         set to 1 to turn API rate limits off
     SPACES_KEY, SPACES_SECRET, SPACES_BUCKET, SPACES_REGION, SPACES_ENDPOINT
                                 all five, or none (photo albums)

   For same-origin (nginx proxies /api and /admin API paths), omit CORS_ORIGIN.
   The deploy user needs passwordless sudo for:
     install -m 600 -o root -g root /tmp/personal-site-api.env.new /etc/personal-site-api.env
   plus install, chgrp, rm, and systemctl for the binary, as below.

4) systemd unit
   cp deploy/personal-site-api.service /etc/systemd/system/personal-site-api.service
   # Edit paths/User in the unit file if your DEPLOY_PATH or user differs.
   systemctl daemon-reload
   systemctl enable --now personal-site-api

5) nginx
   Rate limits (recommended): copy deploy/nginx-http-rate-limits.conf.example to e.g.
     /etc/nginx/conf.d/personal-site-rate-limits.conf
   and ensure /etc/nginx/nginx.conf includes conf.d/*.conf inside http { }.
   Copy deploy/nginx-site.conf.example, set server_name and paths, then:
   nginx -t && systemctl reload nginx
   Limits: ~15 GET/s per IP for static/SPA (burst 40), ~8/s for /api and admin API (burst 24).
   Over-limit clients receive HTTP 429 from nginx before the Go process.

6) TLS (Let’s Encrypt)
   certbot --nginx -d your.domain.example

7) Firewall
   ufw allow OpenSSH
   ufw allow 'Nginx Full'
   ufw enable

8) SSH key for GitHub Actions (deploy user or root)
   On the droplet: ssh-keygen -t ed25519 -C "github-deploy" -f /root/.ssh/github_deploy -N ""
   Authorize for login: cat /root/.ssh/github_deploy.pub >> /root/.ssh/authorized_keys
   Paste the *private* key into GitHub repo secret SSH_PRIVATE_KEY.
   Secrets to set: SSH_HOST, SSH_USER, DEPLOY_PATH (e.g. /var/www/kprovencal), SSH_PRIVATE_KEY,
   plus the API secrets in step 3.

   If rsync fails with "Permission denied" on dist/: ensure DEPLOY_PATH (and dist/) is owned by
   the GitHub SSH user, not www-data.

9) ARM droplets
   If the droplet is aarch64, change GOARCH in .github/workflows/ci.yml (api Build release binary) from amd64 to arm64.

10) API logs on the droplet
   The Go API logs to stderr; systemd captures that in the journal:
     journalctl -u personal-site-api -n 200 --no-pager
     journalctl -u personal-site-api -f
   Nginx (not the Go API):
     /var/log/nginx/access.log
     /var/log/nginx/error.log
   Admin → Logs reads data/api.log (or LOG_PATH). Ensure www-data can create/write it
   (mkdir -p …/data && chown -R www-data:www-data …/data). Avoid LOG_LEVEL=error if you want
   request lines in that file.

11) First deploy
   Push to main after secrets are set. CI writes /etc/personal-site-api.env, uploads dist and the API binary, then restarts personal-site-api.

12) CVE alerts, ops tab, and security updates (no new port)
   After this repo is deployed, Admin → Ops shows API uptime and, once the
   host program has run, kernel/nginx/OpenSSH package status. The status file
   is /var/lib/personal-site/host-status.json, mode 0640 root:www-data.
   GET /healthz on the API is still the text "ok". The example nginx vhost
   proxies location = /healthz; the live certbot file does not until you copy
   that location in. Do not add a "patch" button to the admin UI.

   Workflows (Actions tab):
     Dependabot         weekly PRs for npm, Go modules, and GitHub Actions.
     Host CVE watch     daily SSH, status only, opens an issue if security
                        updates are pending or the loopback API is down.
     Host maintenance   manual, main branch only. Run configure once.
                        That installs unattended-upgrades for the security
                        pocket only, a daily status timer, server_tokens off,
                        and an automatic reboot at 04:15 local time when a
                        reboot is required.
     Uptime             hourly GET / on PUBLIC_SITE_URL (repository variable,
                        https origin, no path). Set that variable or the job
                        stays green and skips. /healthz is an API check only
                        when the body is exactly ok.

   These reuse SSH_HOST, SSH_USER, and SSH_PRIVATE_KEY. Optional secret
   SSH_KNOWN_HOSTS replaces ssh-keyscan. Host maintenance uses the GitHub
   environment production-host; add yourself as a required reviewer if you
   want a second click.

   Host maintenance builds a static linux/amd64 Go binary in CI and installs it
   at /usr/local/sbin/personal-site-host-maint, mode 0755 root:root. The droplet
   does not need a Go or Node toolchain for that program. If the deploy user is
   not root and sudo refuses the program, the job prints one sudoers line.
   Install that as root. It allows only that binary's status, configure, and
   apply commands, not arbitrary commands.

   Kernel CVE-2026-99288 is not fixed in Ubuntu as of 20 Nov 2026. configure
   will not clear it. When Ubuntu later publishes a kernel in the security
   pocket, unattended-upgrades installs it and reboots at 04:15 local time.
   Go stdlib fixes still ship by merging a rebuild to main, not by apt.
